# 资源广场 V1.1 严谨整合方案

## 1. 整合结论

本次工作不是交付研发团队分阶段开发，而是由 Codex 直接完成两套原型的严谨整合。因此不采用分阶段、人日估算、研发排期或分批交付方式，整合完成后统一进行完整验收。

整合采用以下唯一主从关系：

- **功能设计基线**：旧版 `AgentTemplateV3.tsx`。
- **资源类型基线**：旧版资源广场 V3。
- **业务状态与模拟数据基线**：旧版资源广场 V3。
- **全局框架与页面布局风格基线**：`traedemo`。
- **`traedemo` 现有资源广场实现**：不作为功能、数据或交互依据，可以完全替换。
- **旧版知识库管理模块**：不迁移，直接舍弃。
- **个人 API Key**：不从旧版“我的资源”迁移，沿用 `traedemo` 空间管理子 Tab 的现有实现。

整合的目标不是重新设计资源广场，而是在 `traedemo` 的整体视觉体系和应用框架中，完整复现旧版资源广场 V3 的功能设计与演示闭环。

## 4. 必须原样保留的功能设计

### 4.1 资源类型

保持旧版 V3 的四类资源，不扩展为 `traedemo` 当前的七类：

- 模型：`model`
- API：`api`
- MCP：`mcp`
- 知识库资源：`knowledge`

这里的“知识库资源”仅表示资源广场中可发布、授权和使用的资源类型，不包含旧版内嵌的“知识库管理模块”。知识库资源卡片和资源详情必须保留，知识库管理页面必须舍弃。

### 4.2 资源广场

完整保留旧版功能：

- 资源名称、描述、所有权人搜索。
- 全部、模型、API、MCP、知识库分类 Tab。
- 置顶排序和置顶标识。
- 资源类型、子类型、部署方式、描述、所有权人、日期和热度展示。
- 资源详情抽屉。
- 完全公开、公开可见授权可用、仅授权对象可见等公开策略。
- 已授权、仅可见、审核中、已撤销等授权状态。
- 使用申请、授权期限、申请理由和审核中反馈。
- 各资源类型对应的技术配置、Markdown 介绍及对接信息。

#### 资源获取闭环

资源广场不仅负责浏览和申请，还必须保留旧版“获取资源”的完整闭环。获取目标是当前工作空间，获取成功后资源进入该空间的“我的资源”。

| 当前状态 | 页面反馈与操作 | 获取结果 |
| --- | --- | --- |
| 已授权、未获取：`authorized && !isAcquired` | 详情抽屉显示“未获取”和“获取资源”按钮 | 点击后写入当前空间的已获取资源关系，使当前空间视图中的 `isAcquired` 为真，提示获取成功，并出现在当前空间“我的资源”中 |
| 已授权、已获取：`authorized && isAcquired` | 显示“已获授权”，不再展示获取按钮 | 保持已获取状态，可查看资源调用地址，并前往“我的资源”执行安装或更新安装 |
| 仅可见、未授权：`view_only` | 显示“申请使用”按钮 | 填写授权期限和申请理由后提交，状态进入 `reviewing`，同时在权限管理生成待审批记录 |
| 审批中：`reviewing` | 显示审批中提示，禁止重复申请或重复获取 | 审批通过后转为 `authorized + isAcquired`，进入申请空间的“我的资源”；驳回后恢复可申请状态并记录审批意见 |
| 已撤销、已过期或资源已删除 | 不允许重新获取 | 在“我的资源”中按对应失效原因展示，并允许清理失效记录 |

获取流程必须满足：

- 获取动作只能作用于当前空间，不写入其他空间。
- 同一空间与同一资源只能存在一条有效获取关系，重复点击不得产生重复记录。
- 直接获取与审批后获取最终写入同一套空间资源关系，不能维护两套数据。
- 获取成功不等于已经安装；新获取资源进入“我的资源”后，继续保留未安装、安装中、已安装和安装失败状态。
- 切换工作空间后，资源广场中的已获取状态和“我的资源”列表必须按空间重新计算。
- 资源详情中的 API Key 仅提示前往空间管理查看，不在资源广场或我的资源中重复提供凭证管理。

不得用 `traedemo` 当前资源广场的精选推荐、七分类、双列卡片、警务资源数量或调用量换算逻辑替代上述设计。

### 4.3 我的资源

除个人 API Key 外，保留以下旧版功能，并将数据范围调整为当前空间：

- 数据范围限定为当前工作空间已经获取授权的资源，随 `WorkspaceContext` 中当前空间切换。
- 全部、正常、失效状态切换。
- 名称与描述搜索。
- 资源类型和安装状态筛选。
- 正常资源和失效资源展示。
- 已删除、授权过期、授权收回等失效原因。
- 安装、重新安装、安装失败、安装中等状态。
- 最多选择 10 个资源的一键安装。
- 失效资源清理操作。

个人 API Key 不在“我的资源”中迁移或重复实现，统一使用 `traedemo` 空间管理子 Tab 中已经完成的能力。

### 4.4 资源管理

完整保留旧版功能：

- 资源总数及各类型统计。
- 名称、所有权人、类型、发布状态筛选。
- 创建资源流程。
- 从已有工作空间资源选择或直接新建。
- 模型、API、MCP、知识库资源的差异化配置。
- API 手工字段、OpenAPI/Swagger 配置及校验。
- 详情查看、编辑、只读查看。
- 上架、下架、取消发布、置顶。
- 公开策略配置。
- 可见对象和使用对象配置。
- 权限管理、使用申请管理、使用情况和操作日志。
- 资源所有权转移。
- 高风险删除的勾选确认与输入资源名称双重保护。

### 4.5 权限管理

完整保留旧版功能：

- 待审批、审批记录、权限审计三个 Tab。
- 待审批数量提示。
- 按资源名称、资源类型和申请人筛选。
- 申请资源、申请人、申请空间、部门、申请时间、期限和理由展示。
- 审批通过、审批驳回和审批意见。
- 历史审批记录。
- 按个人空间、工作空间和专案空间查看资源权限。
- 批量授权。
- 授权来源、授权时间、到期时间和权限变更记录。

## 6. 目标导航与路由

保留 `traedemo` 全局顶栏、左侧导航、工作空间切换器和多页签框架，按使用侧与管理侧拆分四个入口：

```text
开发中心
└─ 资源广场
   ├─ 资源广场
   └─ 我的资源（当前空间已获取的资源）

管理中心
└─ 资源管理
   ├─ 资源管理
   └─ 权限管理
```

目标路由：

- `/dev/resource-square`
- `/dev/my-resources`
- `/manage/resource-manage`
- `/manage/resource-permissions`

资源广场和我的资源属于当前空间内的资源发现与使用能力；资源管理和权限管理属于平台管理能力，统一放入管理中心。页面位置调整不改变旧版功能内容。

## 7. 页面布局统一规则

页面统一只参考 `traedemo` 的全局设计语言，不参考其现有资源广场页面的具体实现。

统一范围：

- 使用 `AppLayout` 和 `HeaderNav`，不重复渲染旧版全局壳。
- 使用 `WorkspaceContext` 获取当前空间，替代旧版页面内部的空间状态。
- 使用 `TabBar` 管理已打开页面。
- 使用 `traedemo` 的主题色 `#1677ff`、圆角、字体族和页面背景。
- 页面标题、筛选区、内容区、卡片区、表格区采用 `traedemo` 的间距节奏。
- 抽屉、弹窗和表格适配 Ant Design 6 的现行 API。
- 在 1280px 和 1440px 桌面宽度下保持可读性和操作完整性。

不得因统一布局而改变：

- 原有功能入口数量。
- 字段数量和字段含义。
- 操作按钮及其触发结果。
- 筛选条件和状态枚举。
- 抽屉、弹窗中的业务内容。
- 资源类型及模拟数据状态。

## 10. 严谨性控制

### 10.1 功能追踪

为旧版四个入口建立“旧版行为 → 新文件 → 验收结果”映射。除本文明确舍弃项外，任何旧版可见功能必须有明确落点，不允许通过“代码太复杂”或“新版已有类似能力”跳过。

### 10.2 状态一致性

四个页面必须共享状态源，重点核对以下闭环：

```text
创建资源 → 上架 → 资源广场可见
已授权未获取 → 直接获取 → 当前空间的我的资源可见
仅可见未授权 → 申请使用 → 待审批 → 审批通过 → 申请空间的我的资源可见
我的资源 → 安装/失败/重装 → 状态同步
公开策略变更 → 可见范围和申请行为同步
授权撤销/到期/资源删除 → 我的资源转为对应失效状态
```

### 10.3 视觉一致性

视觉验收只比较新页面与 `traedemo` 其他成熟模块的整体一致性，不以 `traedemo` 当前资源广场页面为目标稿。

### 10.4 代码边界

- 资源中心代码不得重新膨胀为单个超大组件。
- 知识库管理代码不得被误带入。
- 不得修改 `traedemo` 其他已完成模块的业务逻辑。
- 不得用新增模拟数据掩盖旧版状态未复现的问题。

## 11. 风险与控制措施

| 风险 | 控制措施 |
| --- | --- |
| 拆分旧版单文件时遗漏功能 | 使用功能追踪表逐项映射，不凭页面印象迁移 |
| 四个路由拆开后状态不再联动 | 使用统一 Context/reducer 复现原单组件共享状态 |
| `traedemo` 当前资源页面逻辑混入 | 替换现有页面入口，不复用其资源类型、Mock 和处理函数 |
| 知识库管理代码被误迁 | 提取时按功能边界排除知识库管理状态、表单、抽屉和事件 |
| 为适配布局而删减旧版功能 | 只允许改变布局与样式，不允许改变字段、状态和操作 |
| 旧依赖安全与包体积问题 | 仅迁移 V3 实际需要的依赖，并对四个路由使用懒加载 |
| Ant Design 6 废弃 API | 在整合时统一替换，不复制已有废弃写法 |
